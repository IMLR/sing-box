2026-11-04：版本 `1.14.2-reF1nd-ax3600-hot1`，新增配置热应用。

运行中的内核收到 SIGHUP、Clash API `PUT /configs` 或 `POST /configs/apply`
时，先重新读取启动时的配置文件，与当前配置逐项比较，只替换变化的部分：

- 出站：新增、修改（同名重建）、删除节点；分组成员变化时原地更新，保留
  当前选择；节点被重建后，持有它的分组改绑到新实例。删除按“先分组、后节点”
  的顺序进行，新规则生效之后才删除。
- 路由规则与规则集定义：新规则全部建好并启动后一次替换；未变化的规则集
  保留原对象和文件监视；被替换的旧规则保留 30 秒，等进行中的匹配结束后才关闭。
- `route.final`。

入站、DNS、日志、实验性选项等其他部分发生变化时什么都不应用，回退到原有的
完整重载。热应用不调用 `check`：`check` 会在进程内另建一份完整实例，路由器
内存承受不起。`POST /configs/apply` 返回本次改动明细，`?reload=true` 时在需要
重载的情况下直接重载。

配套修改：出站管理器删除时先检查依赖再改表，替换时在同一次加锁中换入新实例、
解锁后再关闭旧实例；链式代理（detour）每次拨号重新按名称查找出站，不再缓存
第一次拿到的实例；urltest 分组在成员被重建时按名称保留选择。

测试：`test/box_apply_test.go` 覆盖新增/修改/删除节点、分组成员调整、规则与
规则集增删、需要重载的情况、并发连接下反复应用（`-race`）。用真实路由器配置
（448 个出站、48 个规则集、50 条规则）在 NAS 上实测：每次应用约 15 毫秒，
修改前建立的连接全程可用；交替应用 60 次后强制回收，在用内存 7.3 → 7.4 MB。
