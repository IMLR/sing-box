# AX3600 定制内核

基于 reF1nd/sing-box 修订 `33d41e9bb1d61b3cceacc057cd81bc71d2b1f8aa`（对应
当前路由器正在运行的 sing-boxr 1.13.2，二进制内嵌版本号保持 1.13.2 不变）。

## 变更内容

`go.mod` 将 `github.com/sagernet/sing` 重定向到 `third_party/sing`
（上游 v0.8.2 源码快照，GPL-3.0），其中
`common/bufio/splice_linux.go` 的唯一改动：

```text
maxSpliceSize: 1 << 20  =>  64 << 10
```

## 动机

AX3600 官方固件内核为 Linux 4.4，长期运行后高通 Wi-Fi 驱动造成严重的
内存外部碎片，order-2（16KiB）连续空闲页经常归零。

上游 sing v0.8.2 的 splice 转发会把管道扩容到 1MiB，触发
`pipe_fcntl -> kmalloc_order order=2` 分配。碎片耗尽后分配失败，
内核调用 OOM killer 杀掉 CrashCore。

64KiB 是内核默认管道槽位数（16 页）对应的大小：F_SETPIPE_SZ 到此值时
槽位数组只需 order-0 页，不再依赖连续大块内存。splice 零拷贝转发仍然
生效，300-400Mbps 量级负载下额外系统调用开销可忽略。

## 构建

推送到 `ax3600-splice` 分支即由 GitHub Actions 构建（UPX 压缩产物
`CrashCore.upx`），见 `.github/workflows/ax3600-core.yml`，artifact
名称为 `CrashCore-linux-arm64`。

构建标签与 ShellCrash 当前运行内核一致：
`with_quic,with_utls,with_clash_api,badlinkname,tfogo_checklinkname0`。
